## 1. C++ 面向对象与资源管理

第二课 · O01–O40

## 2. 类、对象与封装

2.1 第一课的结构体把字段组织在一起。本课进一步把操作也放进类型，让每个对象维护自己的状态和使用规则。

配套练习：O01、O02、O03、O04、O05

---

## 3. 类与对象

| 类型定义 | 具体对象 |
| --- | --- |
| 声明成员与操作 | 保存一份具体状态 |
| 说明能做什么 | 对自身接受操作 |

同类型的普通实例分别保存数据

---

## 4. 成员函数作用于当前对象

```cpp
counter.tick();
int value = counter.value();
```

- 点号指定接收操作的对象
- 调用成员函数可以访问该对象的成员
- 另一个实例保留自己的状态

---

## 5. 公开接口与私有数据

| public | private |
| --- | --- |
| 调用方可使用的接口 | 类型内部维护的状态 |
| 表达操作和读取方式 | 集中保护使用规则 |

---

## 6. 状态修改的约定

- 先检查操作前提
- 按接口规定接受、限幅或拒绝
- 失败时保持承诺的状态
- 返回结果帮助调用方决定下一步

---

## 7. struct 与 class

- 两者都能定义数据和成员函数
- struct 的默认成员访问为 public
- class 的默认成员访问为 private
- 访问关键字决定实际接口边界

配套练习：O01、O02、O03、O04、O05

---

## 8. 构造与成员初始化

2.2 一个对象刚出现时，就应该有明确而合法的状态。构造函数负责把这种保证建立起来。

配套练习：O06、O07、O08、O09、O10

---

## 9. 对象的创建过程

| 阶段 | 发生的工作 |
| --- | --- |
| 成员初始化 | 根据声明和初始化列表创建成员 |
| 构造函数体 | 执行额外验证与初始化逻辑 |
| 构造完成 | 调用方使用合法对象 |

---

## 10. 初始化与赋值

- 初始化发生在对象或成员创建时
- 赋值修改已经存在的对象
- const 成员必须在初始化阶段给值
- 成员实际顺序来自类中的声明顺序

---

## 11. 成员初始化列表

```cpp
Sensor::Sensor(int id)
    : id_(id) {
}
```

- 冒号后的内容安排成员初始化
- 函数体执行时成员已经创建

---

## 12. 默认、委托与显式构造

- 默认创建需要可用的默认构造函数
- 委托构造复用同类的构造过程
- explicit 让类型转换意图更明确
- 成员没有默认构造时要传入所需参数

配套练习：O06、O07、O08、O09、O10

---

## 13. 对象的读取、修改与传递

2.3 第一课已经区分副本、引用和指针。把这些机制放到类的接口里，就能看懂 const 方法、this、链式调用和对象容器。

配套练习：O11、O12、O13、O14、O15、O16、O17、O19、O40

---

## 14. const 对象与 const 方法

```cpp
int value() const;
void tick();
```

- 读取接口可以声明为 const
- const 对象只能直接调用适用的 const 接口
- 方法末尾 const 约束对当前对象的访问

---

## 15. this 与当前对象

```cpp
this->x = x;
return *this;
```

- this 指向接收当前调用的对象
- -&gt; 通过指针访问成员
- \*this 表达当前对象本身

---

## 16. 对象接口的返回方式

| 返回方式 | 调用方得到什么 |
| --- | --- |
| T | 独立的值结果 |
| T&amp; | 可修改的借用 |
| const T&amp; | 只读借用 |

引用的有效期由原对象及其状态决定

---

## 17. 复制、引用与静态方法

- 对象复制按成员各自的复制规则进行
- 按值参数使用副本，引用参数借用对象
- 静态成员函数没有当前实例
- 指针成员复制地址，vector 成员复制容器值

---

## 18. 对象集合与类外定义

```cpp
std::vector<Unit> units;
units.emplace_back(id);

void Motor::set(int value) {
    // implementation
}
```

- 容器保存具体对象
- 作用域限定符把定义关联回所属类型

配套练习：O11、O12、O13、O14、O15、O16、O17、O19、O40

---

## 19. 对象组合与协作

2.4 许多功能可以通过多个小对象协作完成。组合把部件作为成员，让外层对象组织步骤而不是包办所有细节。

配套练习：O21、O22、O23、O24、O25

---

## 20. 对象组合

| 外层对象 | 成员对象的责任 |
| --- | --- |
| 底盘 | 协调左右电机 |
| 机器人 | 组织电量和动作 |
| 诊断模块 | 管理消息集合 |

拥有部件的关系用成员对象表达

---

## 21. 对象间的调用顺序

- 外层对象检查动作前提
- 成员对象执行自己的操作
- 返回结果决定是否继续
- 失败时保持约定的整体状态

---

## 22. 配置副本与状态快照

| 构造时的配置副本 | 读取时的状态快照 |
| --- | --- |
| 为对象保存行为参数 | 记录一个时刻的状态 |
| 与调用方配置独立 | 与内部状态独立 |

两者都延续按值复制的语义

---

## 23. 接口统一维护规则

- 限制和过滤集中在类型内部
- 每个成员保留明确责任
- 组合对象协调顺序
- 读取接口说明返回副本还是引用

配套练习：O21、O22、O23、O24、O25

---

## 24. 生命周期、复制与资源管理

2.5 对象何时构造、何时结束，会决定它管理的数据或资源何时可用。析构把结束时需要的工作放进类型本身。

配套练习：O18、O20、O37、O39

---

## 25. 局部对象的生命周期

| 执行过程 | 存活对象 |
| --- | --- |
| 创建外层对象 | a |
| 创建内层对象 | a、b |
| 离开内层 | a |
| 离开外层 | 没有这些局部对象 |

结束作用域会触发相应局部对象的析构

---

## 26. 复制构造与赋值

| 创建副本 | 给现有对象赋值 |
| --- | --- |
| 产生一个新对象 | 对象已经存在 |
| 涉及复制构造 | 涉及复制赋值 |

活对象数要在真正创建和销毁时更新

---

## 27. RAII 的资源责任

- 资源获取与释放成对出现
- 对象承担管理责任
- 对象结束时完成清理
- 标准库成员已经管理自己的存储

---

## 28. 默认行为与禁止复制

```cpp
Device() = default;
Device(const Device&) = delete;
Device& operator=(const Device&) = delete;
```

- 默认行为适合正确组合的成员
- 独占责任可以通过类型禁止复制
- 禁止复制不自动等同于允许移动

配套练习：O18、O20、O37、O39

---

## 29. 继承与基类部分

2.6 组合已经说明“拥有一个部件”。继承用来描述一种更具体的类型与其基类之间的关系。

配套练习：O26、O27、O28、O29、O30

---

## 30. 组合与继承的关系

| 组合 | 公有继承 |
| --- | --- |
| 对象拥有成员部件 | 派生类型具有基类部分 |
| 外层对象协调成员 | 派生对象可使用基类接口 |

先根据类型关系选择结构

---

## 31. 基类构造

```cpp
Derived::Derived(int id)
    : Base(id) {
}
```

- 基类部分先完成构造
- 再构造成员
- 最后执行派生构造函数体

---

## 32. 构造与析构顺序

| 构造 | 析构 |
| --- | --- |
| 基类部分先开始 | 派生析构函数体先执行 |
| 成员按声明顺序创建 | 成员按相反顺序销毁 |
| 派生构造函数体最后执行 | 基类部分最后销毁 |

---

## 33. 继承中的访问边界

- public 提供对外接口
- protected 支持派生实现中的受控访问
- private 保留基类内部边界
- 继承不会开放基类的私有数据

---

## 34. 非虚同名函数

- 派生同名声明会影响名字查找
- 限定名可以明确选择基类实现
- 通过基类调用非虚函数由静态接口决定
- 动态派发需要 virtual 机制

配套练习：O26、O27、O28、O29、O30

---

## 35. 虚函数、多态与对象切片

2.7 调用方有时只关心统一接口，实际行为则由具体对象决定。虚函数让这件事成为 C++ 类型接口的明确组成部分。

配套练习：O31、O32、O33

---

## 36. 虚函数的动态派发

| 调用入口 | 实际选择 |
| --- | --- |
| 基类引用或指针 | 访问其关联的实际对象 |
| virtual 成员函数 | 选择最终覆盖实现 |
| override | 检查覆盖关系是否成立 |

---

## 37. 纯虚接口

```cpp
virtual int read() const = 0;
```

- 抽象类约定统一操作
- 具体派生类提供实现
- 调用方可以依赖基类接口

---

## 38. 值复制与对象切片

| 保存基类值 | 保存基类引用 |
| --- | --- |
| 创建独立 Base 对象 | 借用完整派生对象 |
| 派生部分没有保留 | 派生对象仍然存在 |
| 按 Base 实际类型派发 | 可派发到派生实现 |

动态派发取决于实际保留下来的对象

---

## 39. 多态访问的前提

- 接口函数采用虚调用机制
- 引用或指针关联正确对象
- 对象在调用期间仍然存活
- 拥有关系和借用关系需要明确

配套练习：O31、O32、O33

---

## 40. 动态对象、所有权与异常清理

2.8 普通指针能提供访问入口，析构能完成对象清理。本节把两者连接起来，明确动态对象由谁负责结束生命。

配套练习：O36、O34、O35、O38

---

## 41. 自动对象与动态对象

| 自动局部对象 | 动态创建的对象 |
| --- | --- |
| 离开作用域时结束 | 由拥有者决定结束时机 |
| 生命周期由作用域约束 | 需要明确的清理责任 |

普通指针离开作用域不会自动删除目标

---

## 42. 拥有与借用

| unique\_ptr | 普通指针或引用 |
| --- | --- |
| 承担独占管理责任 | 提供对现有对象的访问 |
| 析构时删除所拥有目标 | 本身不表达自动删除责任 |
| 所有权可以移动 | 借用必须保持目标有效 |

---

## 43. 独占所有权转移

```cpp
std::unique_ptr<T> next = std::move(owner);
```

- std::move 允许选择移动操作
- unique\_ptr 的移动操作转移管理责任
- 转移后的源 unique\_ptr 为空

---

## 44. 多态对象的销毁

```cpp
virtual ~Base() = default;
```

- 通过基类管理派生对象
- 虚析构使相应派生清理参与执行
- 清理沿派生、成员和基类层次完成

---

## 45. 多态容器

```cpp
std::vector<std::unique_ptr<Base>> objects;
```

- 每项管理一个具体对象
- 通过基类接口调用虚函数
- 保存所有者避免按值切片
- 容器结束时由元素完成资源清理

---

## 46. 异常路径与 RAII

| 控制流 | 自动对象的责任 |
| --- | --- |
| 正常离开作用域 | 执行析构清理 |
| 异常传播离开作用域 | 对已经构造的对象执行析构 |
| 匹配 catch | 处理异常并继续相应路径 |

---

## 47. 阅读 C++ 的对象问题

- 值属于什么类型，是否发生复制
- 引用或指针正在访问哪个对象
- 目标在当前使用期间是否存活
- 谁拥有资源，何时完成清理

配套练习：O36、O34、O35、O38
